Project Background

Course: ROB 421 - Cognitive Robotics, Oregon State University, Spring 2026

Course Description: This course is a multidisciplinary hardware project design experience in which small teams of students deliver a culminating end-of-course demonstration of a final robotic system. The class utilizes Vex Aim robots to configure, design, implement, test, and evaluate different functions.

Team Members: Zachary Aszmus, Lucas Dassonville, Perry Johnston, Benjamin Molnar, and Quang Huy Nguyen

Project Focus: The goal of the project is to create two robots that can play a capture the flag style game, where there are four randomly placed ArUco tag “goals”. Each robot has two goals and scores points by placing the correct color barrels by their associated tags.

Why This Project?

We are doing this because we wanted to challenge ourselves with the course content we learned and implemented over the course of the term. Having four separate goal positions as well as 4 separate goal objectives would keep the project unique.

Final Project

Project Description

The project creates two robots that can play a capture the flag style game, where there are four ArUco tag goals. Each robot considers two ArUco tags to be a goal, one for each color barrel, which are orange and blue. Points are scored when a robot picks up and places a barrel at the correct ArUco tag. The robots have the ability to steal from the opposing robot, where it pilots to an opponent's goal, takes a barrel, and brings it to the goal for that color barrel. Success is based on barrel placement success rate and closeness to the correct ArUco tag.

Technical Implementation
  • Hardware: Vex Aim Coding Robot
  • Software Stack: Python, AIM_WEBSOCKET_LIBRARY (link), vex-aim-tools (link)
  • Key Algorithms: Path planning, Object detection, State machines, SLAM
  • Challenges Overcome: The most difficult part of this project was using the aim-fsm system. Though it made the low level finite-state-machine very easy, the documentation for aim-fsm is very lacking, as well as for the vex-aim tools as well. We also stuggled with the robots localizing and seeing their goal tags.

Team Reflections

What We Learned

In this project, we learned much about programming in python and of course, using the vex-aim robots. However, we also learned more general skills, like working in a codebase with multiple people, and working with libraries with limited documentation.

Individual Contributions

Zachary Aszmus: Responsible for making the game interesting by adding random events, such as the robots stopping to tell jokes, changing expressions, and playing noises.

Lucas Dassonville: Responsible for handling the main game loop, starting and ending the game, and ensuring everybody's code is able to work together.

Perry Johnston: Set up the initial framework for the game, planned out the project, and documented the progress.

Benjamin Molnar: Dropping off the barrel while accounting for barrel colors and ArUco tag locations

Quang Huy Nguyen: Picking up barrels, as well as finding which barrels to grab

Future Improvements

Though these robots are typically able to complete the two minute games, there are a few ways the robots can get stuck in a loop and fail to be effective for the rest of the game. The most common of these issues is losing one of its goal tags. If we had more time, we would make a more robust re-localizing system which it can use if it loses its tag.
